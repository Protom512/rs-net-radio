# Agent Collaboration Guidelines

## 概要

このドキュメントは、rs-net-radio プロジェクトにおいて複数のサブエージェントを活用した並列開発を行うためのガイドラインです。

## エージェントタイプと役割

### 1. Explore Agent
- **目的**: コードベースの探索、パターンの発見、理解
- **使用タイミング**:
  - 新しいモジュールを理解する必要がある時
  - 特定のパターンをコードベース全体から探す時
  - 実装前に影響範囲を調査する時
- **例**: 「record-lib 内のエラーハンドリングパターンを調査」

### 2. General-purpose Agent
- **目的**: 実装、リファクタリング、テスト作成
- **使用タイミング**:
  - 新しい機能を実装する時
  - 複数のモジュールを並行して修正する時
  - テストを書く時
- **例**: 「Hibiki サービスのエラーハンドリングを実装」

### 3. Bash Agent
- **目的**: コマンド実行、ビルド、テスト
- **使用タイミング**:
  - 長時間実行されるコマンド
  - 複数のテストを並行実行
- **例**: バックグラウンドでのテスト実行

## 並列実行のパターン

### パターン1: 調査 + 実装の並列化

```
タスク: 「record-lib に包括的なエラーハンドリングを追加」

並列実行:
- Agent 1 (Explore): 既存のエラーハンドリングパターンを調査
- Agent 2 (General): ドメイン層のエラー型を実装
- Agent 3 (General): インフラ層のエラー型を実装
- Agent 4 (General): エラーの統合テストを作成
```

### パターン2: モジュール並行実装

```
タスク: 「新しいラジオサービス XYZ を追加」

並列実行:
- Agent 1: RecordService trait の実装
- Agent 2: スクレイピングロジックの実装
- Agent 3: 設定管理の実装
- Agent 4: ドキュメントとテストの作成
```

### パターン3: テスト駆動並列開発

```
タスク: 「Hibiki サービスの機能追加」

並列実行:
- Agent 1: 失敗するテストを先に記述 (TDDのRedフェーズ)
- Agent 2: テストを通すための実装 (Greenフェーズ)
- Agent 3: 既存コードのリファクタリング (Refactorフェーズ)
- Agent 4: 統合テストの実行
```

## 並列実行のベストプラクティス

### 1. 依存関係のないタスクを選ぶ

並列実行するタスクは、互いに独立している必要があります。

**良い例**:
- 異なるモジュールの実装
- 異なるテストファイルの作成
- 調査と実装（実装は調査結果を待たない）

**悪い例**:
- 同一ファイルの修正（衝突の原因）
- 依存関係にあるモジュール（順序が必要）

### 2. 単一メッセージで複数のエージェントを起動

真の並列実行のため、1つのメッセージで複数の Task ツールを呼び出します。

```rust
// 推奨: 単一メッセージで複数の Task を呼び出す
Task 1: Explore...
Task 2: General...
Task 3: General...

// 非推奨: 順次起動（並列にならない）
Task 1: Explore... (待機)
Task 2: General... (待機)
```

### 3. 明確な役割分担

各エージェントに明確な責任を割り当てます。

- 重複した作業を避ける
- 結果の統合方法を事前に決める
- 競合を避けるためのファイル単位での分離

### 4. 結果の統合

すべてのエージェントが完了したら:
1. すべての変更をマージ
2. ビルドとテストを実行
3. 結果を要約して報告

## コマンド

### /rust:agents

複数のエージェントを並行起動してタスクを実行します。

```bash
/rust:agents "record-lib に包括的なエラーハンドリングを追加"
```

### 手動での並列実行

直接 Task ツールを使用して、カスタマイズされた並列実行を行います。

## 設定ファイル

以下の Gemini カスタムコマンドが利用可能です:

- `/rust:test` - テスト実行
- `/rust:build` - ビルド
- `/rust:clippy` - リンター
- `/rust:fmt` - フォーマット
- `/rust:doc` - ドキュメント生成
- `/rust:fix` - 自動修正
- `/rust:expand` - マクロ展開
- `/rust:watch` - ファイル監視
- `/rust:agents` - 並列エージェント実行

## 注意事項

1. **過剰な並列化は避ける**: 多くのエージェントを起動しすぎると、結果の統合が困難になります
2. **コンテキストの共有**: エージェント間で共有すべき情報は明確に伝えます
3. **品質の確保**: 並列実行後は必ず統合テストを実行します
